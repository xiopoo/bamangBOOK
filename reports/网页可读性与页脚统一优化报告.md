> 审查日期：2026-08-01　对象：bamang.vercel.app 全部静态导出页面（3,537 个 HTML）
> 结论前置：本站在 2026-07 已建立完整的中文阅读排版系统（reading.css v2，WCAG AAA），

### 1.3 一项已由既有机制解决的隐患（确认有效，未重复处理）

## 二、结构优化措施（已实施）

### 2.1 页脚统一（处理 E）

**做法**：将 `PageFooter`（`src/components/PageFooter.tsx`）从各页面手工引用改为**根布局统一渲染**。

- `src/app/layout.tsx`：`<main>{children}</main>` 之后、`<BackToTop />` 之前加入 `<PageFooter />`
- 删除 **39 个页面**的 `import PageFooter` + `<PageFooter />` 引用（脚本按整行精确删除）
- 删除 **9 个详情页**的一行字极简页脚（`qa/[id]`、`books/[slug]`、`interviews/[id]`、`talks/[id]`、`columns/[slug]`、`partnership/[id]`、`letters/[year]`、`business-history/[slug]`、`bloggers/[blogger]/[id]`）
- 删除 checkout 页的第 3 种页脚与对应死 CSS `.checkout-footer`
- 页脚结构（全站唯一标准）：品牌区（复利书房 + 印章「研」+ 品牌语）→ 主要栏目导航（10 项）→ 关注我们（公众号二维码 + 小红书）→ 版权与合规行（© 2026 复利书房 · 不构成投资建议）。移动端沿用既有响应式断点（`@media (max-width: 640px)` 单列堆叠）。

**构建产物验证**：3,537 个 HTML 页面中 **3,537 个含统一页脚（100%）**；浏览器实测 QA 长文页与首页页脚结构完全一致（高约 351px，四段完整）。

### 2.2 博主列表页：年份跳转 + 旧年份折叠（处理 C）

`src/app/bloggers/[blogger]/page.tsx`：

- **年份快速跳转**：年份数 > 6 时，页面顶部出现「2016–2026」胶囊链接，点击锚点 `#year-YYYY` 平滑定位（`scroll-mt-24` 抵消 sticky 头部）
- **默认折叠**：最近 3 年默认展开，更早年份折叠为 `<details>` 卡片（`summary` 内保留年份标题 + 篇数徽章 + 展开指示箭头），点击即展开，无需 JS（原生 `<details>/<summary>`，SEO 语义完整，h2 保留）

**默认渲染量对比**（按 2026-08-01 索引实测）：

| 博主 | 总篇数 | 年份数 | 改前默认渲染 | 改后默认渲染 | DOM 减少 |
|---|---|---|---|---|---|
| 在苍茫中传灯 | 947 | 11 | 947 条（100%） | 223 条（24%） | **76%** |
| 梁孝永康 | 511 | 11 | 511 条（100%） | 60 条（12%） | **88%** |
| 方伟看十年 | 735 | 8 | 735 条（100%） | 543 条（74%） | 26% |
| 唐僧的碎碎念 | 445 | 3 | 445 条（100%） | 445 条（100%） | 0%（仅 3 年，全部保留） |

浏览器实测：11 个年份卡片仅 3 个默认展开；点击年份胶囊跳转正确；点击折叠行可展开。

### 2.3 博主详情页：补章节目录（处理 D）

`src/app/bloggers/[blogger]/[id]/page.tsx`：新增 `<ArticleTableOfContents />`（与 QA/股东信/演讲等详情页同一组件），置于正文右侧。

- 行为与其他详情页完全一致：文章含 h2–h4 时显示桌面 sticky 目录 + 移动端折叠抽屉；无标题文章按组件设计自动不显示（避免空目录）
- 进度条与字号控件原本已有，确认保留
- 浏览器实测：TOC 机制在含 20 个章节的 QA 长文中正常渲染与跳转；微信体无标题文章不显示目录（符合预期）

### 2.4 排版与语义核验（处理 A/B —— 已达标项，确认无需改动）

`src/app/reading.css`（CN Reading Typography v2）经核验已覆盖用户要求的全部排版维度：

- **字号**：正文 19px 默认，用户可调 17–26px（`--text-size-base`，无 FOUC）
- **行高**：正文 1.88（移动端 1.92），段距 1.6em，首行缩进 2em
- **对比度**：正文 #2b2318 于纸底、辅助文 #5d5448、标题 #1a1410，均达 WCAG AAA（7:1）；暗色模式单独校准 ≥ 6.5:1
- **行长**：39em（中文约 39 字/行）
- **标题语义**：H1 页面级唯一；正文 H2/H3 带 id 锚点 + 赭红装饰；QA 模式问题行自动提升为 H2/H3 结构
- **长文导航**：ArticleTableOfContents（桌面 sticky + 移动折叠抽屉）、ReadingProgress 顶部进度条、BackToTop、上下篇导航
- **响应式**：640px 断点（行高加大、行长放开、表格缩字、导航叠放、≥20px 安全边距、iPhone 安全区适配）

**关于分页的决策**：QA/股东信等单篇长文（最长 98KB）**不做分页**。原因：内容是按年份组织的原始记录，单篇即一个完整事件，强行分页会割裂上下文与检索定位；已有 TOC/进度/锚点导航覆盖了「长文可定位」需求。博主列表页的「折叠」即渐进式披露（progressive disclosure），达到分页/无限滚动要解决的「首屏不过载」目标，且不丢内容、无需客户端状态。

## 四、关于用户行为指标（平均停留时长 / 滚动深度 / 互动）的说明

**本站是 Next.js 静态导出站点，未接入任何统计埋点（无 Vercel Analytics / GA）**，
因此「改前 vs 改后」的**真实用户行为数据无法回测**。上表用的是可复算的结构性代理指标
（DOM 规模、页脚覆盖率、可导航章节数），它们与可读性正相关但不等同于行为指标。

若要获得你要的行为指标，建议下一步：

1. 在 `layout.tsx` 接入 **Vercel Web Analytics**（免费，一行 `<Analytics />`，无需改页面），
   可给出各页面平均停留时长与访问漏斗；
2. 对滚动深度做轻量埋点（`IntersectionObserver` 记录 25/50/75/100% 滚动阈值，
   参考 `ReadingProgress` 现有实现）；
3. 部署后观察 2–4 周，重点对比：`/bloggers/[blogger]` 列表页的**滚动深度**与**二次展开行为**、
   `/bloggers/[blogger]/[id]` 详情页的**跳出率**、全站页脚的**页内点击**。
