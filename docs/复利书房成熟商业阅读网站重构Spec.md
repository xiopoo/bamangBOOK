# 复利书房成熟商业阅读网站重构 Spec

## 1. 文档信息

- **状态**：待评审、待执行
- **版本**：v2.0
- **日期**：2026-08-10
- **项目目标**：将复利书房从内容数量庞大、页面各自组织的资料聚合站，重构为具有明确编辑立场、稳定内容模型、统一阅读模板、完整可信度说明和可持续商业能力的长期投资阅读档案馆。
- **基准产品**：借鉴 Munger Archive 的档案组织、编辑推荐、元数据展示、来源说明和内容入口设计；不照搬其单人物信息架构、英文排版尺度或移动端实现。
- **适用范围**：内容数据、路由、导航、首页、目录页、详情页、专题页、搜索、编辑可信度、视觉系统、响应式、SEO、可访问性、性能、商业入口和工程验收。
- **不在本期范围**：重新翻译全部原典、重写全部公司研究、重新制作 PDF、接入真实支付或账户服务、引入新的内容来源、重新设计品牌名称和 Logo。

## 2. 重构背景与问题结论

### 2.1 当前状态判断

当前网站已经拥有足够丰富的内容资产，但产品层尚未形成统一秩序。主要表现为：

1. 数据对象与页面链接之间缺少稳定契约，已经出现坏链接和静态路由错误；
2. 首页展示的是“系统取出的内容”，而不是经过编辑定义的“值得现在阅读的内容”；
3. 人物、内容类型、公司研究和阅读路径在不同页面中采用不同层级；
4. 详情页可信度组件只在少数模板落地，尚未成为全站规范；
5. CSS 通过重复规则和高优先级覆盖维持，响应式行为不稳定；
6. 内容规模很大，但用户难以判断从哪里开始、为什么值得读、资料是否完整；
7. 商业阅读产品所需的可信度、编辑推荐、连续阅读和内容修订机制尚未完整形成。

### 2.2 已确认的 P0 故障

以下问题必须在任何视觉重构之前完成修复：

| 编号 | 问题 | 当前表现 | 影响 | 完成标准 |
|---|---|---|---|---|
| P0-01 | 首页最近更新坏链接 | 内容链接生成 `/talks/undefined` | 用户无法进入内容，破坏可信度 | 首页不存在 `undefined`、空 slug 或 404 内容链接 |
| P0-02 | 最近更新语义错误 | 展示旧年份内容但命名为最近更新 | 用户无法理解“更新”含义 | 明确区分首次发布、内容年份和最近修订 |
| P0-03 | 公司研究详情路由 500 | 中文编码 slug 与 `generateStaticParams()` 不一致 | 公司研究主路径不可用 | 目录中的每个详情链接在开发、构建和部署产物中均返回 200 |
| P0-04 | 导航文字可换行 | 桌面导航没有强制单行 | 生产字体、缩放或临界宽度下标签分行 | 所有一级导航标签保持单行；空间不足时提前进入移动导航 |
| P0-05 | 中文标题断词 | 移动端标题出现“判 / 断”等单字断裂 | 首屏显得粗糙且不可控 | 关键标题按语义控制换行，不出现不合理单字孤行 |
| P0-06 | 原始文件名外露 | 阅读总库显示 `partnership_1956-*` | 暴露内部数据结构，降低成熟度 | 所有用户界面只显示编辑标题，不显示文件名或内部编号 |

### 2.3 已确认的结构性问题

- `ReadingMetadata` 和 `SourceNote` 尚未成为全站详情页基础能力；
- 页面存在统一组件名称，但不同内容类型仍自行实现列表、元数据和上一篇/下一篇；
- 段永平拥有大量内容，却在阅读总库中处于“继续探索”层；
- 施洛斯被放入核心人物统计，与产品定位不一致；
- 公司研究入口同时承担公司索引、商业主题和深度研究，概念边界不清；
- 公司研究目录重复展示英文公司名，状态、修订时间和完整度缺失；
- `globals.css` 与阅读样式文件体积过大，存在大量 `!important`、重复断点和历史选择器；
- 账户、订单和结算路由仍存在，但产品状态与导航策略没有统一声明；
- 部分页面有独立 SEO 元数据，部分依赖继承，无法保证每个页面唯一且准确。

## 3. 产品定位

### 3.1 核心定位

> 复利书房是一个以巴菲特、芒格、段永平原典为核心，延伸到公司研究和商业史的长期投资阅读档案馆。

### 3.2 用户承诺

用户进入网站后，应在 10 秒内理解：

1. 网站保存哪些资料；
2. 今天可以从哪里开始读；
3. 每条资料如何说明来源、翻译、完整度和修订状态；
4. 如何按人物、年份、内容类型和主题继续阅读。

### 3.3 编辑立场

网站不以“收录越多越好”为唯一目标，而以以下原则组织内容：

- 原典优先于解读；
- 完整上下文优先于金句摘录；
- 可验证来源优先于未经核对的转载；
- 编辑推荐优先于算法随机展示；
- 连续阅读优先于无限信息流；
- 明确标注不完整，比隐藏缺漏更重要；
- 公司研究必须区分事实、来源和编辑判断。

### 3.4 内容层级

| 层级 | 内容 | 产品角色 | 首页权重 |
|---|---|---|---|
| 核心原典 | 巴菲特、芒格、段永平的信件、问答、演讲、访谈 | 网站主体 | 最高 |
| 研究延伸 | 公司研究、商业史、资本配置案例 | 帮助理解原典 | 高 |
| 学习辅助 | 思维模型、书籍、博主文章、阅读路径 | 帮助建立体系 | 中 |
| 商业产品 | 巴芒文集、纸质或数字产品 | 支持持续运营 | 低，不压过阅读 |
| 账户能力 | 登录、订单、交付 | 交易基础设施 | 未完成前不公开推广 |

施洛斯、李录、经典书籍和博主文章可以保留，但不得在核心人物层与巴菲特、芒格、段永平同级展示。

## 4. 借鉴 Munger Archive 的范围

### 4.1 必须借鉴的产品方式

1. **一句话档案承诺**：首页首屏用一句可验证的描述说明内容范围与整理原则；
2. **今日推荐**：提供一条明确推荐的资料，并说明“为什么今天值得读”；
3. **档案抽屉**：用少量稳定入口解释档案如何分类，而不是堆叠全部栏目；
4. **皇冠内容**：由编辑维护“从这里开始”的核心内容，不由发布时间自动决定；
5. **目录元数据**：每条目录内容显示年份、类型、媒介或状态、阅读时长；
6. **内容描述**：目录条目用一两句话说明内容价值，不只展示标题；
7. **来源纪律**：明确原始来源、是否嵌入或转载、是否完整、是否经过核对；
8. **纠错机制**：页脚和详情页均提供反馈入口；
9. **编辑而非信息流**：首页模块由编辑目的驱动，不做无限滚动内容流。

### 4.2 不应照搬的部分

- Munger Archive 是单人物站点，复利书房需要处理三位核心人物和公司研究；
- 英文超大标题不能直接套用到中文，中文必须进行语义换行控制；
- 移动端不复制其可见导航换行方式，复利书房使用明确的移动菜单；
- 不复制装饰字体和颜色本身，重点复制信息优先级和编辑秩序；
- 不把全部栏目拉到一级导航；
- 不把商业产品混入档案抽屉或核心原典推荐。

## 5. 目标信息架构

### 5.1 一级导航

全站固定为四个内容栏目：

```text
原典档案
公司研究
阅读路径
关于
```

全站搜索为工具入口，不占用内容栏目位置。深色模式为图标工具，不进入栏目结构。

### 5.2 二级结构

```text
原典档案
├── 总览
├── 巴菲特
├── 芒格
├── 段永平
├── 信件
├── 股东大会问答
└── 演讲与访谈

公司研究
├── 深度研究
├── 公司索引
└── 商业主题

阅读路径
├── 新读者从这里开始
├── 从第一封合伙人信开始
├── 巴菲特阅读路径
├── 芒格阅读路径
├── 段永平阅读路径
└── 主题阅读

关于
├── 关于复利书房
├── 来源与编辑原则
├── 修订记录
└── 联系与纠错
```

### 5.3 一级导航交互规则

- 桌面端一级标签禁止换行；
- 从可能发生挤压的宽度之前进入移动导航，不使用临界点硬撑；
- 桌面端下拉内容最多两列，不使用 38rem 的空壳大面板；
- 每个下拉入口必须拥有唯一目标，不允许两个标签指向同一路径但表达不同职责；
- 支持点击、键盘 Enter/Space、方向键或 Tab、Escape 关闭、点击外部关闭；
- `aria-expanded`、`aria-controls`、`aria-haspopup` 与实际状态一致；
- 下拉打开后焦点可进入，关闭后焦点返回触发按钮；
- 移动菜单打开后锁定页面背景滚动，Escape 和关闭按钮均可退出；
- 移动菜单搜索入口使用统一工具样式，不得出现未匹配 class；
- 所有触控目标最小 44×44px。

### 5.4 URL 与 canonical 规则

#### 5.4.1 原则

- 一个内容只允许一个 canonical URL；
- URL 参数和静态生成参数使用同一种编码策略；
- 内部数据保存原始稳定 slug，视图层只在生成 URL 时编码一次；
- 服务端取参后只解码一次；
- 禁止在多个层级重复 `encodeURIComponent` 或 `decodeURIComponent`；
- 中文 slug 可以保留，但不允许继续使用带编号、文件扩展名或编辑状态的内部文件名作为公开 URL；
- 已经被外部引用的旧 URL 通过重定向表迁移，不直接删除。

#### 5.4.2 目标路由

```text
/archive                         原典档案总览
/archive/buffett                 巴菲特专题
/archive/munger                  芒格专题
/archive/duan-yongping           段永平专题
/letters                         信件目录
/letters/[year]                  股东信详情
/partnership/[id]                合伙人信详情
/qa                              问答目录
/qa/[id]                         问答详情
/talks                           演讲与访谈目录
/talks/[slug]                    演讲或访谈详情
/research                        公司研究目录的稳定主入口
/research/[slug]                 公司研究详情
/companies                       公司索引
/topics/[slug]                   商业或投资主题
/paths                           阅读路径总览
/paths/[slug]                    阅读路径详情
/about                           关于
/about/editorial                 来源与编辑原则
/about/revisions                 修订记录
```

本期可以保留现有 `/business-history`、`/buffett`、`/munger` 等路径，但必须明确 canonical 和未来迁移表。不能同时让 `/research` 和 `/business-history` 都成为可索引主入口。

### 5.5 路由可靠性约束

- 每个动态路由必须由同一数据源生成目录链接和 `generateStaticParams()`；
- 构建前自动检查“列表 href 集合”是否为“静态参数集合”的子集；
- 构建后检查全部静态详情页文件存在；
- 关键目录中的每个链接必须进行 HTTP 200 验证；
- 路由测试必须覆盖中文、空格、英文标点、弯引号和混合语言 slug；
- 禁止把 `fileName`、`id`、`slug` 当成可以相互替代的可选字段。

## 6. 统一内容数据模型

### 6.1 核心类型

```ts
type ContentType =
  | '合伙人信'
  | '股东信'
  | '股东大会'
  | '演讲'
  | '访谈'
  | '公司研究'
  | '商业史'
  | '文章'
  | '书籍'

type ContentStatus =
  | '原文'
  | '译文'
  | '编辑整理'
  | '已校对'
  | '部分内容缺失'
  | '待核对'

type Completeness = '完整' | '部分' | '未知'

type ReadingContent = {
  id: string
  slug: string
  href: string
  canonicalPath: string
  title: string
  shortTitle?: string
  dek?: string
  personIds: string[]
  companyIds?: string[]
  year?: number
  date?: string
  contentType: ContentType
  sourceLabel: string
  sourceUrl?: string
  sourcePublisher?: string
  sourceDocument?: string
  status: ContentStatus
  translated: boolean
  translationMethod?: string
  editorMethod?: string
  reviewedAt?: string
  publishedAt?: string
  updatedAt?: string
  readMinutes: number
  completeness: Completeness
  missingNote?: string
  topics: string[]
  body: string
  previousId?: string
  nextId?: string
}
```

### 6.2 字段约束

- `id`：永久稳定，不因标题修改而改变；
- `slug`：公开路径标识，不允许为空；
- `href`：由路由函数生成，不允许在页面中手写拼接；
- `title`：用户可见标题，不从文件名直接回退；
- `dek`：一至两句说明“这篇内容讲什么、为什么值得读”；
- `personIds`：使用稳定 ID，不在数据层混用中英文姓名；
- `sourceLabel`：所有可读内容必填；
- `status`：所有可读内容必填，不能默认掩盖未知状态；
- `readMinutes`：必须为正整数，计算规则全站一致；
- `completeness`：所有核心原典必填；
- `reviewedAt`：已校对、译文和编辑整理内容应填写；
- `body`：正文和索引元数据分离，目录页不得加载完整正文。

### 6.3 禁止的回退行为

以下写法不得继续存在：

```ts
item.slug || item.id
item.title || fileName
item.href || `/talks/${item.slug || item.id}`
```

数据进入页面之前必须经过规范化和校验。缺少公开字段的内容应在构建阶段报错，不能生成 `/undefined` 或把文件名展示给用户。

### 6.4 日期语义

必须区分：

| 字段 | 含义 | 使用位置 |
|---|---|---|
| `year` / `date` | 原始内容发生或发布的时间 | 目录排序、详情元数据 |
| `publishedAt` | 内容首次在复利书房上线的时间 | 新上线内容 |
| `updatedAt` | 页面最后一次内容变更 | 最近更新 |
| `reviewedAt` | 最近一次人工核对时间 | 可信度说明 |

“最近更新”必须按 `updatedAt` 排序，不得使用原始内容年份替代。

### 6.5 内容质量校验

构建前执行以下检查：

- slug、href、canonical 不为空；
- href 中不存在 `undefined`、`null`、`.md`；
- 标题不等于文件名；
- 核心原典有来源、状态和完整度；
- `sourceUrl` 存在时必须为合法 URL；
- `reviewedAt` 和 `updatedAt` 使用 ISO 日期；
- 同一 canonical 不对应多个内容 ID；
- 同一 ID 不对应多个 canonical；
- 前后篇引用必须存在；
- 内容状态和 `translated` 不矛盾；
- “已校对”内容必须有 `reviewedAt`。

## 7. 页面模板

全站只保留四种主要内容模板。业务页面不得自行复制同类视觉结构。

### 7.1 首页模板

#### 7.1.1 页面目标

首页不是完整目录，也不是宣传海报。它负责在最短时间内回答：网站是什么、今天读什么、怎样继续找、为什么可信。

#### 7.1.2 模块顺序

1. **品牌定位首屏**
   - 一条 kicker；
   - 一个主标题；
   - 一段不超过 90 个汉字的说明；
   - 一个主要动作“开始阅读”；
   - 一个次级文字链接“了解整理方法”；
2. **三个基础入口**
   - 按人物；
   - 按年份；
   - 按主题；
3. **今日推荐**
   - 一条编辑精选内容；
   - 年份、类型、阅读时长、状态；
   - 80—160 字推荐理由；
4. **档案抽屉**
   - 巴菲特；
   - 芒格；
   - 段永平；
   - 信件；
   - 问答与演讲；
   - 公司研究；
   - 每个抽屉显示数量和用途说明；
5. **从这里开始**
   - 最多三条皇冠阅读路径；
6. **最近修订**
   - 3—6 条；
   - 按 `updatedAt` 排序；
   - 显示修订日期和状态；
7. **编辑说明**
   - 来源、翻译、校对、完整度和纠错原则；
8. **低干扰产品入口**
   - 只说明文集适合连续阅读；
   - 不使用抢夺首屏注意力的购买按钮。

#### 7.1.3 首页硬性约束

- 首屏只允许一个 H1 和一个主要按钮；
- 390px 宽度下 H1 不出现单字孤行；
- 首次滚动一屏以内出现可点击内容；
- 不展示自动拼接但无法解释的“最近更新”；
- 不同时展示完整人物介绍、全部统计、产品销售和全部分类；
- 今日推荐必须由显式配置或编辑字段产生；
- 首页所有内容链接必须通过统一路由函数生成。

### 7.2 目录页模板

#### 7.2.1 适用范围

- 信件；
- 问答；
- 演讲与访谈；
- 公司研究；
- 人物资料目录；
- 全部内容；
- 公司索引和主题索引的列表部分。

#### 7.2.2 页面结构

1. 面包屑；
2. 页面标题和一句编辑说明；
3. 紧凑统计条；
4. 筛选和排序；
5. 连续列表；
6. 分页或分年折叠；
7. 目录说明；
8. 页脚。

#### 7.2.3 标准筛选

根据内容集合显示以下维度：

- 人物；
- 年份或年代；
- 内容类型；
- 内容状态；
- 主题；
- 公司；
- 排序方向。

筛选状态必须反映到 URL 查询参数，刷新和分享后保持一致。

#### 7.2.4 标准目录行

每行至少包含：

```text
年份/日期
标题
一句内容说明（可选但推荐）
人物 · 类型 · 阅读时长
内容状态
进入箭头
```

状态不能只用颜色表达，必须同时显示文本。

#### 7.2.5 长目录规则

- 61 封股东信允许按年代分组，但首屏应看到首组有效条目；
- 超过 100 条使用分页、分年或虚拟化，不渲染隐藏正文；
- 段永平大量内容必须分页，并支持年份和类型筛选；
- 不允许同一页同时混用卡片、表格和抽屉表达同一内容集合；
- 目录行不得显示内部文件名；
- 排序方向必须在筛选区或统计条中明确显示。

### 7.3 详情页模板

#### 7.3.1 页面结构

1. 面包屑或返回目录；
2. 标题和副标题；
3. 阅读元数据；
4. 内容可信度摘要；
5. 阅读工具；
6. 正文；
7. 章节目录；
8. 来源与编辑说明；
9. 上一篇 / 下一篇；
10. 相关文章或同年内容；
11. 纠错入口。

#### 7.3.2 顶部元数据

统一显示两行：

```text
人物 · 年份/日期 · 类型 · 阅读时长
来源 · 内容状态 · 完整度 · 最近修订
```

公司研究替换人物字段为公司名称，但其余规则不变。

#### 7.3.3 来源与编辑说明

页面底部统一显示：

- 原始来源名称；
- 原始来源链接或本地来源说明；
- 翻译或整理方式；
- 是否完整；
- 已知缺漏；
- 最近修订日期；
- 最近核对日期；
- 发现错误后的反馈方式。

不得向用户显示本地工程路径，例如：

```text
content/companies-studies/Disney.pdf
```

应转换为用户可理解的来源名称和必要链接。

#### 7.3.4 前后篇规则

- 列表为从早到晚时，上一篇是更早内容，下一篇是更晚内容；
- 列表为从新到旧时，界面必须明确说明方向；
- 前后篇标题、年份和方向同时显示；
- 第一篇和最后一篇保留占位或单边布局，不发生跳动；
- 公司研究必须提供稳定的上一篇/下一篇，不用随机“继续阅读”替代；
- 相关内容与前后篇是两个不同模块。

#### 7.3.5 阅读体验

- 正文宽度 `39—44em`；
- 桌面正文行高 `1.8—1.85`；
- 移动正文行高 `1.85—1.9`；
- 段落间距 `1.1—1.25em`；
- 支持字号调整并持久化；
- 支持深色模式；
- 支持阅读位置恢复；
- 长文支持章节目录；
- 章节目录不可遮挡正文；
- 打印样式隐藏导航、推荐和商业入口，保留标题与来源。

### 7.4 专题页模板

#### 7.4.1 适用范围

- 巴菲特；
- 芒格；
- 段永平；
- 公司研究总览；
- 单一主题；
- 阅读路径。

#### 7.4.2 页面结构

1. 专题定位；
2. 为什么值得读；
3. 推荐阅读顺序；
4. 主要资料入口；
5. 皇冠内容；
6. 最近修订；
7. 延伸内容。

专题页解释内容之间的关系，不重复完整目录，不承担产品销售页职责。

### 7.5 搜索页

- 支持标题、人物、公司、年份、主题和正文关键词；
- 搜索结果显示内容类型、年份、人物和状态；
- 不显示文件路径；

- 搜索结果 href 使用统一路由模型；
- 结果数量过大时分页；
- 搜索词在标题和摘要中可访问地高亮；
- 不因高亮破坏屏幕阅读器语义。

### 8.1 组件边界

- `SiteHeader` 和 `MobileNavigation` 共用同一导航配置；
- 所有状态标签由一个枚举映射表提供文本、图标和样式。

### 8.2 组件验收

- 不存在功能相同但名称不同的页面级组件；
- 四种主模板全部使用统一页头、面包屑和页脚；
- 所有核心详情页使用 `ReadingMetadata`、`SourceNote` 和 `ReadingNavigation`；
- 所有目录页使用 `ArchiveList` 或明确声明的索引变体；
- 组件可在深色和浅色模式下工作；
- 组件在 320、390、768、1024、1280、1440px 下无溢出。

## 9. 视觉系统

### 9.1 设计方向

视觉关键词：编辑档案、安静、可信、长期阅读、克制商业化。

视觉不依赖大量卡片、渐变、统计图标和装饰性背景。主要通过字体层级、留白、细分隔线、纸张色、墨色和低饱和强调色形成气质。

### 9.2 三层密度

| 层级 | 页面 | 规则 |
|---|---|---|
| 展示层 | 首页、专题页 | 少量重点、较大标题、明确编辑推荐 |
| 目录层 | 档案、列表、索引 | 紧凑、连续、可快速扫描 |
| 阅读层 | 信件、问答、研究详情 | 正文舒适、元数据克制、工具稳定 |

### 9.3 中文排版

- H1 必须支持显式语义换行；
- 不允许关键短语被拆成单字孤行；
- 使用 `text-wrap: balance` 时必须验证中文实际效果；
- 必要时通过可响应的换行标记控制桌面和移动版本；
- 标点不应单独出现在行首；
- 元数据、数字和英文名称避免不必要断行；
- 导航、按钮和状态标签统一 `white-space: nowrap`。

### 9.4 尺寸和间距

- 目录页最大宽度：`72rem`；
- 正文宽度：`39—44em`；
- 首页展示区块间距：`2.5—3rem`；
- 专题页区块间距：`2.5rem`；
- 目录区块间距：`1.5—2rem`；
- 目录行内边距：`0.75—1.1rem`；
- 移动端页面左右边距：最小 `1rem`；
- 首屏不得通过无理由 `min-height` 制造大块空白。

### 9.5 响应式断点策略

断点由内容是否开始拥挤决定，不沿用当前“900px 前硬撑”的规则。

建议基线：

```text
< 48rem       移动布局
48—68rem      平板与紧凑桌面布局
> 68rem       完整桌面导航
```

最终断点必须通过实际中文导航、Logo、搜索和主题按钮的总宽度验证，不得只凭设备名称确定。

- 阅读总库样式不再单独演化成第二套全局系统；

### 10.3 CSS 验收指标

- 同一断点规则按模块集中；
- `globals.css` 只保留令牌、reset 和真正全局规则；
- 删除移动菜单 class 名不一致问题；
- 视觉回归测试中无横向滚动条。

## 11. 首页编辑运营机制

### 11.1 今日推荐配置

```ts
type HomepageRecommendation = {
  contentId: string
  reason: string
  featuredFrom: string
  featuredUntil?: string
```

若配置内容不存在，构建失败或回退到经过验证的固定皇冠内容，不得生成空链接。

### 11.2 皇冠内容

每位核心人物维护 3—8 条核心内容，字段包括：

- 内容 ID；
- 推荐顺序；
- 推荐理由；
- 适合读者；
- 前置阅读；
- 编辑更新时间。

### 11.3 最近修订

- 只读取拥有合法 `updatedAt` 的内容；
- 显示“2026-08-10 修订”，不以原文年份冒充更新时间；
- 可以说明本次修订内容，如“补充原始来源”“修正译文”“补齐缺失章节”；
- 同一内容短期多次修订只显示一条；
- 最多显示 6 条。

## 15. SEO

### 15.1 基础要求

- 每个可索引页面拥有唯一 title、description 和 canonical；
- 详情页 title 包含人物或公司、年份和资料类型；
- 专题页 title 清楚表达主题，不使用泛化标题；
- canonical 使用最终公开域名和唯一主路径；
- 旧路径通过永久重定向指向 canonical；
- 搜索参数页根据策略 canonical 到目录主页面或设置 `noindex`；
- 登录、订单、结算、隐私账户页设置正确索引策略；
- sitemap 只包含返回 200 的 canonical 页面；
- robots 不屏蔽需要索引的正文资源。

### 15.2 结构化数据

- 网站使用 `WebSite`；
- 面包屑使用 `BreadcrumbList`；
- 原典和研究详情根据内容使用 `Article` 或 `ScholarlyArticle`；
- `datePublished` 对应内容上线日期，不冒用原典年份；
- `dateModified` 对应网站修订日期；
- 作者、编辑和来源关系表达准确；
- 不为无法验证的评分、价格或作者关系生成结构化数据。

### 15.3 自动检查

- 统计无显式唯一 metadata 的页面；
- 检查重复 title、description、canonical；
- sitemap URL 全部返回 200；
- canonical 不含编码两次的字符；
- 不存在指向 404/500 的内部链接。

## 16. 可访问性

- 所有交互元素可使用键盘；
- 焦点样式清晰，不能仅依赖颜色；
- 跳转正文链接在键盘聚焦时可见；
- 下拉导航和移动菜单状态正确播报；
- 筛选控件有 label；
- 状态标签包含文本；
- 图标按钮有可访问名称；
- 图片 alt 描述信息作用，不重复附近文字；
- 装饰图标设置 `aria-hidden`；
- 深浅模式文本对比满足 WCAG AA；
- 正文放大到 200% 仍可阅读；
- 320px 下不出现双向滚动；
- 动画尊重 `prefers-reduced-motion`；
- 阅读进度条不干扰屏幕阅读器。

## 17. 性能

- 目录页不加载完整正文；
- 大目录分页或分年按需渲染；
- 首页不读取无关内容全集；
- 字体数量和字重保持克制，提供回退字体；
- 避免因 Web Font 加载导致导航宽度突变；
- 首屏无大尺寸无用途图片；
- 交互组件只在需要时使用客户端 JavaScript；
- 章节目录和阅读位置恢复不得阻塞正文显示；
- 构建产物不包含重复的大型索引数据；
- 关键页面 Core Web Vitals 在真实部署环境验证。

## 18. 深色模式与阅读状态

- 主题偏好存储在本地并尊重系统设置；
- 首次渲染不闪烁错误主题；
- 字号偏好在详情页之间保持；
- 阅读位置按 canonical 内容 ID 保存；
- 内容重大修订后允许使旧进度失效或进行版本迁移；
- 提供“回到上次位置”和“从头开始”；
- 不把登录作为保存本地阅读状态的前提。

## 21. 迁移策略

### 21.1 页面迁移顺序

```text
股东信详情样板
→ 合伙人信
→ 演讲与访谈
→ 股东大会问答
→ 公司研究
→ 段永平大量内容
→ 人物专题
→ 首页
→ 辅助内容
```

### 21.2 CSS 迁移方法

每迁移一个模板：

1. 建立新组件和模块样式；
2. 将该模板全部页面切换到新组件；
3. 完成视觉和交互验证；
4. 删除对应历史规则；
5. 检查未使用 class；
6. 再进入下一模板。

不得保留新旧两套组件长期并行，也不得在迁移过程中通过文件末尾覆盖旧规则。

### 21.3 URL 迁移

- 输出旧 URL → 新 URL 映射表；
- 保留高价值旧 URL；
- 为迁移路径建立永久重定向；
- 更新内部链接、canonical、sitemap；
- 部署前检查重定向链不超过一跳；
- 不允许旧 URL 和新 URL 同时返回可索引 200 正文。

## 23. 发布门禁

以下任一条件存在时不得发布：

- 首页存在空链接、`undefined` 链接或 404；
- 公司研究目录存在详情页 500；
- 构建失败；
- 关键导航在任一验收视口断行或溢出；
- 核心内容缺少来源或状态；
- canonical 重复；
- 上一篇/下一篇方向与目录排序不一致；
- 新增临时 CSS 覆盖规则；
- 移动菜单无法使用键盘或无法关闭；
- 未完成登录或支付入口重新进入主导航。

## 24. 完成定义

项目只有在以下条件同时满足时才算完成：

1. 所有 P0 故障已修复并有自动化回归检查；
2. 内容数据使用统一 schema，不再依赖 `slug || id` 等隐式回退；
3. 核心人物、内容类型、公司研究和阅读路径层级清楚；
4. 首页形成“定位—今日推荐—档案抽屉—皇冠内容—最近修订—编辑说明”的完整编辑路径；
5. 所有核心目录页使用统一连续目录模板；
6. 所有核心详情页使用统一元数据、来源说明和前后篇导航；
7. 段永平资料进入核心原典体系并支持大规模分页筛选；
8. 公司研究目录和全部详情路由稳定可用；
9. CSS 不再依赖持续追加的历史覆盖规则；
10. 导航、中文标题、正文和移动菜单通过完整响应式矩阵；
11. SEO、可访问性、性能和内部链接检查通过；
12. 未完成商业功能不干扰主要阅读体验；
13. 构建成功，关键路由和部署环境验证全部通过。
